# Literature Review

What learned index structures have been proposed, and under which data distributions and update workloads do they outperform or underperform traditional indexes?

## Summary
Learned index structures replace traditional indexing components with machine learning models to predict key positions, offering significant performance and memory advantages in specific in-memory, read-heavy workloads [3, 4, 7]. However, their performance is highly sensitive to data distributions, access patterns, and the overhead introduced by dynamic updates [2, 3]. While several architectures have been proposed to handle updates and skewed data [2, 3, 4], traditional B+-trees still outperform learned indexes in disk-resident and write-heavy scenarios due to higher block write overheads in learned structures [1, 5].

## Architectures and Update Mechanisms
The original learned index structure replaces a standard database index with a hierarchy of machine learning models trained on the Cumulative Distribution Function (CDF) to predict key positions in a densely packed array, requiring a bounded range search for inaccuracies [3, 4]. This original design is limited to static, read-only workloads but achieves up to three times faster search times and an order of magnitude smaller memory footprint compared to a B+-tree [3, 4]. Because the original learned index lacks support for update operations, it is unusable for broader database workloads [4]. 

To support dynamic workloads, subsequent architectures have introduced various adaptations, though incorporating updates into structures like ALEX and PGM-index incurs extra search overhead for lookup operations [3]. ALEX utilizes a Gapped Array node layout with model-based inserts and an adaptive Recursive Model Index (RMI) structure driven by cost models [3, 4]. However, ALEX suffers from an unbounded "last mile" search cost in its leaf nodes during lookups due to a lack of error thresholds [3]. The PGM-index handles updates using the logarithmic method, which requires searching for keys across a series of subtrees instead of a single tree [3]. LIPP is an updatable learned index with precise positions that employs a dynamic adjustment strategy to tightly bound tree height, allowing it to outperform state-of-the-art solutions by up to 4× across various index operations [3]. Maintenance overhead during insertions also varies by architecture; ALEX reduces maintenance overhead compared to LIPP during insertions because ALEX only updates one data node, whereas LIPP updates all nodes in the access path [1]. 

Beyond one-dimensional sorted arrays, learned indexes have been adapted for diverse settings, including secondary indexes, multi-dimensional data, spatial data, string data, and in-memory concurrency support [5]. For instance, LIMS addresses similarity search in metric spaces by partitioning data into clusters with uniform distributions using pivots and using machine learning models to approximate record positions on disk [8].

## Impact of Data Distributions and Access Patterns
The relative performance of learned and traditional indexes is heavily influenced by data distributions and access patterns. Current learned indexes often assume static data distributions and uniform access patterns, which hinders their applicability in real-world scenarios [2, 3]. Highly non-uniform datasets and skewed access patterns make it difficult for learned models to depict overall distributions, increasing tree height and making mispredictions of frequently queried hot keys highly expensive [2, 3]. To address skewed queries and dynamic data, the Doraemon system augments training data with access frequencies to improve latency [2]. Conversely, widely used trie-based traditional indexes perform best with near-uniform data distributions and require structural optimizations like dynamic fanout or node aggregation to adapt to less ideal distributions [2]. 

Despite these challenges, some learned indexes demonstrate robustness to distribution shifts. ALEX maintains a performance advantage under distribution shifts caused by data skew without requiring hand-tuned parameters [4]. At the micro-architectural level, ALEX is primarily bound by memory stalls, specifically data misses from the last-level cache, but exhibits fewer stalls and a lower cycles-per-instruction value than ART and B+-tree [6].

## Performance Comparisons Across Workloads
The performance advantages of learned indexes are highly dependent on the specific combination of data distribution, workload type, and storage medium [7]. 

On read-only in-memory workloads searching over dense arrays, learned index structures provide Pareto dominant performance and memory size behavior compared to traditional indexes, an advantage largely explained by cache misses rather than any single specific metric [7]. Among learned structures, Recursive Model Indexes (RMIs) provide the strongest performance-to-size ratio but incur the longest build times, whereas RS and PGM indexes build faster but have slightly slower lookup times [7]. LIPP significantly outperforms other learned indexes, including ALEX and PGM, in lookup-only and read-only workloads [1, 3]. ALEX also achieves higher throughput and significantly smaller index sizes compared to B+-tree, the original Learned Index, Model B+-tree, and ART on read-only workloads, beating the original Learned Index by up to 2.2× in performance with up to 15× smaller index size [4].

In write-only workloads, PGM achieves the best performance among evaluated learned indexes [1]. For read-write workloads, LIPP outperforms ALEX, PGM, B+-tree, and ART, though the performance of all evaluated methods decreases as the proportion of insert operations increases [3]. ALEX consistently outperforms B+-tree across the read-write workload spectrum by up to 4.1× with up to 2000× smaller index size, maintaining an advantage under distribution shifts caused by data skew [4].

Despite in-memory successes, on-disk updatable learned indexes do not achieve competitive performance to standard B+-trees across workload types [1, 5]. B+-trees outperform learned indexes in the majority of disk-resident read-write cases because learned indexes incur a higher number of block writes [1, 5].

## Limitations and Open Problems
The primary limitation of current learned indexes is their assumption of static data distributions and uniform access patterns, which hinders applicability in real-world scenarios with evolving data and skewed queries [2, 3]. Furthermore, while in-memory read-only performance is strong, on-disk updatable learned indexes struggle to match the performance of traditional B+-trees due to high block write overheads [1, 5]. Future design of on-disk, updatable learned indexes should focus on reducing tree height, improving data structures to lower operation overheads, enhancing scan operation efficiency, and optimizing storage layout [1].
