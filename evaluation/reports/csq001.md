# Literature Review

What are the main methods for evaluating retrieval-augmented generation systems, and which retrieval and generation dimensions do they measure?

## Summary
Evaluating retrieval-augmented generation (RAG) systems requires a multifaceted approach that measures distinct retrieval and generation dimensions [1, 2]. Current methods range from automated, reference-free frameworks and multimodal benchmarks to human-in-the-loop enterprise evaluations [1, 2, 5, 6]. These approaches assess retrieval through context relevance and selection accuracy, while generation is measured via faithfulness, correctness, and hallucination detection [1, 2, 7]. However, traditional metrics often fall short in capturing real-world usage, closed-model performance, and domain-specific variability, highlighting the need for specialized, context-aware evaluation frameworks [2, 3, 5].

## Frameworks for Retrieval and Generation Dimensions
RAG evaluation frameworks are designed to isolate and measure the specific contributions of the retrieval and generation components. For the retrieval dimension, the RAG-Check framework introduces a Relevancy Score (RS) to quantitatively measure the selection process, assessing how relevant retrieved multimodal documents are to the user query [1]. The Ragas framework evaluates context relevance, though it identifies this as the most difficult dimension to evaluate automatically [2]. 

For the generation dimension, RAG-Check utilizes a Correctness Score (CS) that partitions the generated response into text spans, categorizes them as subjective or objective, and scores how correctly each span reflects the raw context [1]. Ragas measures generation faithfulness and answer relevance, demonstrating that its reference-free predictions align closely with human judgments for these dimensions [2]. Other tools, such as LlamaIndex, rely on large language models like GPT-4 to evaluate the faithfulness of generated responses [1]. Additionally, end-to-end evaluation frameworks incorporate specialized mechanisms for hallucination detection, such as using nearest-neighbor embedding classifiers to identify potential pipeline hallucinations [7]. To assess overall output quality, some approaches employ a multi-metric scoring framework that combines SequenceMatcher, BLEU, METEOR, and BERT Score to evaluate accuracy and relevance [4].

## Multimodal, Efficiency, and Domain-Specific Evaluation
Evaluating RAG systems extends beyond text to encompass multimodal generation, computational efficiency, and domain-specific performance. In retrieval-augmented image generation, benchmarks like GenEval measure the percentage of images that correctly align with text descriptions across attributes, composition, and counting, while DPG-Bench evaluates the handling of detailed, complex prompts [6]. These are supplemented by metrics such as FID for statistical similarity, CMMD for CLIP-based human perception alignment, and FWD for spatial and frequency coherence [6]. However, evaluations using these benchmarks reveal that some previous retrieval-augmented image methods actually perform worse than their non-retrieval counterparts [6].

To capture computational trade-offs, the OmniBench-RAG platform utilizes a dual-track automated evaluation architecture that compares vanilla and RAG-enhanced models, quantifying performance gains across accuracy and computational efficiency metrics, including latency, GPU utilization, and memory consumption [3]. Furthermore, this platform demonstrates that RAG effectiveness exhibits striking variability across different knowledge fields, yielding significant accuracy gains in domains like culture but performance declines in mathematics, which underscores the critical need for systematic, domain-aware assessment [3].

## Limitations of Traditional Metrics and Enterprise Evaluation
Traditional evaluation methods often fail to capture the complexities of real-world RAG deployments. Evaluating RAG systems using language modeling perplexity is not always predictive of downstream performance and is inaccessible for closed models, while standard question-answering evaluations typically rely on short extractive answers that do not represent real-world usage [2]. 

In enterprise settings, common benchmark techniques are ineffective for evaluating novel user questions, necessitating a "human in the lead" approach that relies on manual fact-checking across questions, retrieved content, and generated answers [5]. Enterprise evaluations also identify specific points of failure within the RAG pipeline, including missing content, search failures, context window limitations, poor LLM generation, incorrect output formats, and vague answers [5].

## Limitations and Open Problems
Despite advancements in RAG evaluation, several limitations and open problems remain. Automating the evaluation of context relevance continues to be a significant challenge, as models often struggle to select crucial sentences from longer contexts [2]. Standard metrics like perplexity and extractive question-answering remain insufficient for evaluating closed models and complex, real-world generative tasks [2]. Furthermore, the reliance on manual, human-in-the-loop fact-checking for novel enterprise queries limits the scalability of evaluation pipelines [5]. Finally, retrieval augmentation does not universally improve system performance, as evidenced by degradations in both specific image generation tasks [6] and specialized knowledge domains like mathematics [3], indicating that evaluation frameworks must be highly sensitive to domain and modality constraints.
