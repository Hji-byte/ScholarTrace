# Literature Review

How do graph-based, quantization-based, and inverted-file approaches to approximate nearest-neighbor search compare in recall, latency, memory usage, and index construction cost?

## Summary
Approximate nearest-neighbor search (ANNS) methods inherently involve trade-offs among accuracy, search speed, and memory consumption, making the optimal choice highly dependent on the scale and constraints of the problem [7]. Graph-based methods generally offer the best balance of accuracy and search speed for million-scale datasets but are constrained by host memory and suffer from long index construction times [7, 8]. Quantization-based approaches significantly reduce memory overhead but can suffer substantial recall degradation under aggressive compression [6]. For billion-scale datasets, where memory becomes a primary bottleneck, inverted-file and disk-based hybrid approaches have emerged as highly efficient solutions, achieving state-of-the-art performance with minimal memory costs and cheap serving overhead [5].

## Graph-Based Approaches: Search Performance and Construction Costs
Graph-based ANNS algorithms excel in expressing neighbor relationships, allowing them to evaluate fewer points to achieve high accuracy compared to other methods in Euclidean space [1, 3]. Consequently, they provide the best balance of accuracy and search speed for million-scale datasets [7]. For example, the graph-based framework VSAG achieves higher recall (89.80% vs. 84.57%) and queries-per-second at target recall levels compared to the quantization-based inverted-file method IVFPQFS, albeit with a larger memory footprint (4.5G vs. 3.8G) [4]. Furthermore, optimized graph frameworks like VSAG significantly reduce parameter tuning costs (e.g., 2.92 hours) through automated tuning, compared to over 20 hours for IVFPQFS and over 60 hours for standard HNSW [4].

Despite their search efficiency, graph-based methods suffer from long index construction times because constructing the underlying K-nearest neighbor graph is highly time-consuming, and direct construction approaches remain slow due to the need for high accuracy during the build phase [3, 7]. Algorithmic optimizations, such as the P2K and K2P techniques in FastNSG, reduce redundant distance and angle computations to greatly speed up index construction without altering the final graph [2]. Optimized methods like FastNSG and FastHNSW achieve significantly lower construction costs while maintaining or improving search performance compared to other state-of-the-art proximity graph methods like DiskANN [2]. However, broadly accelerating index construction often results in noticeably inferior search performance compared to methods that do not prioritize construction speed [2]. Additionally, applying machine-learning-based optimizations to graph methods improves the speedup-versus-recall trade-off but significantly increases both index construction time and memory consumption [1]. 

While graph-based methods achieve high query efficiency and recall, their scalability is strictly constrained by available host memory [8]. Disk-based approaches attempt to mitigate these memory constraints by offloading data to SSDs, but they introduce new challenges, such as long I/O traversal paths and high in-memory indexing overhead [8].

## Quantization and Inverted-File Approaches: Memory Efficiency and Billion-Scale Scaling
Quantization-based methods are primarily utilized to significantly reduce the memory overhead of ANNS systems [6]. However, this memory reduction comes at a direct cost to search accuracy. Aggressive memory reduction, such as compressing vectors by 16x, can result in a substantial decrease in recall, such as a 25% drop, because standard quantization processes often fail to carry the inherent features required for effective graph-based routing [6]. In terms of index construction time, low-rank matrix factorization methods like LoRANN generally offer faster index construction times compared to graph-based methods like HNSW, although they can be slower than some specific quantization-based implementations like IVFPQfs [9].

The explosive growth of vector scales has made memory a critical bottleneck for in-memory ANNS algorithms, highlighting the necessity for approaches that minimize memory costs at the billion scale [5]. While most traditional ANNS algorithms focus on fast, high-recall search entirely in memory, few address the memory constraints of billion-scale datasets [5]. Inverted-file approaches, such as SPANN, address this by storing only centroid points in memory while placing large posting lists on disk. This memory-disk hybrid methodology achieves state-of-the-art recall, latency, and memory costs for large-scale and billion-scale datasets [5]. SPANN allows for a direct trade-off between the number of centroids, memory usage, and search performance [5]. Furthermore, inverted-file methods can be built extremely quickly; using hierarchical balanced clustering (HBC) for centroid selection, the entire SPANN index can be constructed in around 2 minutes [5]. While disk-based graph methods like DiskANN combine quantized vectors in memory with a graph on disk to offer high recall and low latency, simple inverted index approaches can achieve comparable state-of-the-art performance with significantly cheaper serving costs [5].

## Direct Methodological Comparisons
Evaluating ANNS algorithms requires measuring multiple dimensions, including index construction efficiency, index size, search efficiency, accuracy, and memory overhead [1]. Direct comparisons demonstrate that graph-based methods outperform quantization-based methods in Euclidean space because their ability to express neighbor relationships allows them to check fewer points to reach the same accuracy, thereby reducing search time [1, 3]. 

Graph-based methods inherently involve a trade-off between accuracy, speed, and memory consumption, making the appropriate method highly dependent on the scale of the problem [7]. For million-scale datasets, graph-based methods provide the best balance of accuracy and search speed [7]. However, when scaling to billion-sized datasets, the memory limitations of purely in-memory graph methods become prohibitive [5, 8]. In these regimes, inverted-file methods that leverage disk storage for posting lists provide a highly efficient alternative, matching or exceeding the performance of disk-based graph methods while maintaining cheap serving costs and rapid index construction times [5].

## Limitations and Open Problems
Current ANNS methodologies face distinct limitations depending on the scale and hardware constraints. Graph-based methods, while offering superior search performance for million-scale datasets, are fundamentally limited by host memory capacity and suffer from prohibitively long index construction times [3, 7, 8]. Disk-based and hybrid graph approaches mitigate memory limits but introduce significant I/O latency and traversal overhead [8]. Quantization-based methods effectively reduce memory footprints but struggle with severe recall degradation under aggressive compression [6]. While inverted-file methods like SPANN demonstrate excellent scalability and cheap serving costs for billion-scale data, the available evidence primarily focuses on specific implementations; broader comparative benchmarks evaluating the construction costs and latency of inverted-file methods against next-generation graph and quantization methods across diverse billion-scale datasets remain limited.
