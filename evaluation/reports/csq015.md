# Literature Review

What are the main approaches for reducing communication and latency costs in Byzantine fault-tolerant consensus protocols?

## Summary
Byzantine fault-tolerant (BFT) consensus protocols face significant scalability challenges, primarily driven by high communication costs and latency [2]. This review examines the main approaches used to mitigate these overheads, categorizing them into techniques for reducing message complexity and bandwidth, methods for optimizing round complexity and latency, and structural or architectural changes designed to scale consensus. While various protocols achieve linear message complexity or reduced latency through cryptographic optimizations, probabilistic models, and architectural decoupling [1, 5], fundamental tradeoffs between communication steps, latency, and throughput remain prominent open challenges [2, 8].

## Reducing Message Complexity and Bandwidth
Traditional BFT protocols often rely on all-to-all communication patterns, resulting in quadratic message complexity [2]. To address this, protocols like HotStuff reduce message complexity to linear by shifting to a leader-to-all-to-leader exchange pattern [2]. Alternative network topologies, such as tree-based message exchange patterns and gossip layers, are also utilized to improve message complexity and balance system load [2]. Furthermore, collector nodes can aggregate messages; for example, Linear Hybster uses a collector to aggregate Commit messages, reducing quadratic communication to linear at the cost of an additional communication step [1].

Cryptographic and hardware optimizations further decrease communication overhead. The DQBFT protocol achieves linear communication costs by employing threshold signatures and hardware-assisted trusted subsystems to decrease the required quorum size [1]. Similarly, threshold cryptography and trusted subsystems can be combined to attain optimal linear communication [1]. For bandwidth-intensive operations, HBBFT adapts erasure codes and Merkle trees from verifiable information dispersal to achieve amortized O(n) communication complexity for large input batches [5].

Probabilistic and targeted communication methods also reduce bandwidth requirements. The Musch protocol reduces communication complexity from O(n^2) to O(fn + n) without compromising latency by introducing exponentially increasing windows of nodes for complaint reporting, rather than broadcasting to all nodes [3]. Probabilistic BFT approaches can achieve a high probability of agreement while exchanging only 18-25% of the messages required by baseline protocols like PBFT [2], and ProBFT reduces message complexity to O(n√n) using probabilistic quorums [2]. Additionally, routing transactions to a random subset of replicas can effectively reduce bandwidth in larger systems compared to full command dissemination [1].

## Optimizing Latency and Round Complexity
Reducing message complexity often introduces a tradeoff with latency. Approaches that avoid all-to-all communication patterns typically trade reduced message complexity for an increased number of communication steps, as seen in HotStuff, which adds extra steps that increase end-to-end response times [2]. Many partially synchronous BFT protocols adopt a pessimistic approach to ensure safety under worst-case adversary scenarios, which typically results in increased message complexity or communication steps [2].

To optimize latency, some protocols involve clients directly or optimize voting mechanisms. Zyzzyva lowers latency by involving clients to assist in validations [4]. In dynamically available systems, integrating a pre-commit mechanism with publicly verifiable secret sharing (PVSS) reduces communication rounds to four network delays in common scenarios while maintaining resilience against up to half adversarial participants [6]. In asynchronous BFT, the Dumbo protocol optimizes the latency-critical phase by replacing multiple slow asynchronous binary Byzantine agreements (ABBAs) with a single asynchronous multi-valued validated Byzantine agreement (MVBA) [5]. 

Leaderless and multi-leader designs also target latency reduction. Ocior achieves two-round latency in fully asynchronous settings by utilizing a leaderless design that processes transactions individually and concurrently using parallel consensus instances [9]. BigBFT reduces latency and increases throughput by enabling every node to act as a leader to propose and order blocks in parallel, removing the single-leader bottleneck [8]. It achieves an amortized O(n) communication cost by piggybacking votes, pipelining blocks, and using only two communication steps in the common case, while maintaining linear O(N) message complexity even during worst-case leader cascading failures by overlapping the propose-vote and coordination phases [8]. In DAG-based BFT, the Shoal framework improves the latency of Narwhal-based protocols through a more efficient ordering rule and a leader reputation mechanism [7], while other theoretical efforts reduce latency by trading off the non-equivocation property of the DAG construction [7].

## Architectural and Structural Scalability
Structural changes are often necessary to scale BFT consensus and overcome the limitations of traditional designs. Traditional primary-backup BFT protocols suffer from performance bottlenecks and load imbalances because a designated primary replica is solely responsible for ordering and replicating commands [1]. To address throughput bottlenecks caused by combined replication and ordering tasks, protocols like SDPaxos and DQBFT separate the replication of commands from the global ordering process, decentralizing the heavy replication task [1].

Architectural decoupling is also applied to improve responsiveness in web services. A two-layer architecture can reduce latency by using a session-aware transaction buffer layer to deliver immediate feedback to users through consensus simulation, while periodically committing batched operations to a fully BFT consensus layer [4]. This separation addresses the fundamental tension between security and responsiveness in interactive applications [4].

## Limitations and Open Problems
Despite significant progress, several limitations and tradeoffs remain in optimizing BFT consensus. A primary challenge is the inherent tradeoff between message complexity and latency; approaches that avoid all-to-all communication patterns typically trade reduced message complexity for an increased number of communication steps [2]. Furthermore, in asynchronous BFT protocols, achieving linear amortized communication complexity often requires broadcasting huge batches of transactions to maximize throughput, which dramatically sacrifices latency [5]. Even with de-duplication techniques that route transactions to a small subset of nodes, guaranteeing liveness against asynchronous adversaries still incurs O(n) redundant communication in the worst case [5]. Finally, many protocols for partially synchronous systems rely on pessimistic approaches to ensure safety under worst-case scenarios, which inherently increases message complexity or communication steps, highlighting the need for approaches that can accommodate more realistic adversaries without sacrificing performance [2].
