# Literature Review

What are the main neural and large-language-model-based approaches to automated program repair, and how do they generate and validate patches?

## Summary
Automated Program Repair (APR) has evolved from traditional Generate and Validate paradigms [2, 3] to advanced neural and large language model (LLM)-based approaches. These modern techniques frame repair as tasks like neural machine translation [5] or leverage iterative conversational, search-based, and hybrid generation strategies [1, 3, 4]. While they demonstrate significant promise in generating plausible patches, they rely heavily on test-based validation, which can be computationally expensive [5]. Furthermore, challenges remain regarding model interpretability [6], resource consumption [5], and the ability of LLMs to fully capture program semantics and structural constraints [8].

## Architectures and Representations in Neural and LLM-based APR
Traditional Automated Program Repair (APR) approaches commonly use a Generate and Validate (G&V) paradigm, where candidate patches are generated and sequentially validated against test cases until a plausible patch is found [2, 3]. Within this traditional landscape, template-based techniques are limited in their ability to handle previously unseen bugs due to their dependence on predefined transformation templates [3], while redundancy-based techniques, such as GenProg, generate patches by directly reusing existing code under the guidance of genetic programming algorithms [6]. 

In contrast, learning-based APR techniques often frame the repair process as a neural machine translation (NMT) task, utilizing encoder-decoder architectures to translate buggy code sequences into correct code sequences [5]. While some learning-based models treat source code purely as natural language sequences, this limits their ability to capture underlying code structure features such as data flow or control flow [5]. To address this, standard NMT models have been augmented with tree-based encoders, such as Abstract Syntax Trees (ASTs) paired with tree-based RNNs or bidirectional LSTMs, to better capture code structures [5]. 

Large language model (LLM)-based repair approaches encompass a variety of strategies, including NMT, cloze-style repair where buggy lines are masked for inference, instruction and chat-based methods, and frameworks utilizing iterative LLM calls [1]. However, most LLMs treat programs as sequences of tokens, making them ignorant of the underlying semantic constraints of the target programming language [8]. Furthermore, large pre-trained repair models, such as CodeBERT, consume significant device resources, posing challenges for deployment in modern integrated development environments [5].

## Patch Generation Strategies
Neural and LLM-based models employ diverse strategies to generate candidate patches. Prior LLM-based approaches that repeatedly sampled the model using the same prompt often generated the same incorrect patches repeatedly and missed critical information present in test cases [2]. To overcome this, conversational APR alternates between patch generation and validation in a conversational manner, iteratively building model inputs by combining previously generated patches with validation feedback and leveraging long-term context windows to avoid repeating incorrect patches [2]. Other frameworks, such as the Round-Trip Translation (RTT) pipeline, generate candidate patches through a four-step process comprising preprocessing, translation generation, postprocessing, and validation [1]. The CURE technique improves upon earlier neural models by pre-training a programming language model on a large corpus and employing a code-aware beam search strategy to prevent the generation of uncompilable patches [5].

Effective patch search is a central bottleneck in LLM-based APR, requiring systems to allocate limited search budgets to decide which intermediate candidate patches deserve further refinement [3]. To address the weakly structured, trial-and-error patch generation of existing methods, search-based frameworks like PSearch have been introduced to better allocate these budgets [3]. PSearch utilizes APR-specific reasoning by prompting the model to explicitly analyze the bug, the current partial patch, and observed test failures before generating new candidate patches [3]. Additionally, the GIANT REPAIR approach leverages LLM-generated patches to construct a patch skeleton and constrain the patch space, followed by a context-aware skeleton instantiation process to generate tailored patches [4]. Fusing LLMs with completion engines, as seen in the Repilot system, consistently improves the validity and correctness of generated patches with minimal computational overhead [8]. Because existing LLM-based methods often utilize generated patches without further optimization, hybrid approaches combining LLMs with program analysis have been motivated to incorporate program-specific knowledge [4].

## Patch Validation and Verification
Validating and verifying generated patches is a critical step in both traditional and learning-based APR. Test-based patch validation requires that previously passing test suites continue to pass on the patched program while fault-triggering test suites begin to pass [5]. Learning-based techniques typically adopt this test-based validation strategy to automatically filter out candidate patches that fail to compile or do not pass available test suites, thereby reducing manual inspection effort [5]. However, compiling and executing test suites for a large number of candidate patches to identify plausible ones is an extremely time-consuming process [5]. 

To manage this, systems like GIANT REPAIR utilize frameworks such as ExpressAPR to manage test execution, identifying plausible patches by verifying if LLM-generated candidate patches pass all associated test cases [4]. Alternatively, the PracAPR system incorporates a program re-execution-free patch validation step alongside LLM-based local repair and tailored strategy-driven global repair [7]. In conversation-based LLM repair methods, runtime feedback is incorporated through iterative dialogue, but the inherent stochasticity of LLM outputs necessitates multiple repair attempts, resulting in substantial computational and financial costs [9]. To address these high costs, token-efficient approaches like CigaR have been introduced to minimize token overhead [9].

## Limitations and Open Problems
Despite their promise, neural and LLM-based APR approaches face several limitations. LLM-based approaches suffer from interpretability issues because deep neural networks are typically used in a black-box fashion with complex and random natures [6]. Furthermore, treating programs as sequences of tokens limits the models' understanding of underlying semantic constraints [8], and treating source code as natural language sequences restricts the capture of structural features [5]. The deployment of large pre-trained models is also hindered by their significant consumption of device resources [5]. Finally, conversation-based methods incur substantial computational and financial costs due to the stochasticity of LLM outputs requiring multiple repair attempts [9].
