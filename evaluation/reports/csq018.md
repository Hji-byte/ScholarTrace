# Literature Review

How have programmable data planes and in-network computing evolved, and which classes of distributed applications have benefited from them?

## Summary
The evolution of programmable data planes has transitioned from dedicated hardware middleboxes to generic, fully programmable network architectures encompassing switches, programmable NICs, and SmartNICs [1, 8]. This progression has enabled a wide array of distributed applications—ranging from key-value stores and distributed machine learning to network monitoring and high-performance computing—to offload computation to the network [1, 2, 6]. While in-network computing provides substantial performance benefits, such as order-of-magnitude throughput improvements and reduced latency, its adoption is constrained by the limited memory and computational resources of current switching ASICs [1, 2, 5]. Addressing these hardware limitations through efficient algorithm design, model compression, and advanced programming frameworks remains a critical open problem [2, 4].

## Architectural Evolution and Hardware Progression
The concept of data plane programming was initially discussed in the 2000s with the advent of merchant chips but became a practical reality around 2015 [1, 8]. Historically, in-network computation relied on dedicated network accelerator middleboxes, but the field has evolved toward generic programmable data plane hardware architectures and foundational frameworks such as IncBricks [1, 8]. A fully programmable network architecture now consists of both a programmable data plane and a programmable control plane, which together enable the systematic reconfiguration of low-level packet processing steps to drive next-generation network services [1, 8]. 

This architectural evolution is characterized by two parallel trends: the emergence of increasingly demanding applications that require capabilities beyond current programmable switching ASICs, and the development of diverse data plane technologies [2]. Furthermore, programmable data plane hardware has expanded beyond its initial focus on data center switches to encompass a broader range of devices. Today, programmability extends to general network processing middleboxes, programmable network interface cards (NICs), and SmartNICs situated at the host-network boundary [1].

## Distributed Applications and Performance Benefits
Distributed applications that benefit most from data plane offloading typically process massive amounts of network-bound data, possess stringent latency or throughput requirements, or can be decomposed into simple packet processing primitives [1, 2]. By leveraging in-network aggregation, applications that utilize partition and aggregation patterns can overcome previous deployment limitations and achieve order-of-magnitude throughput improvements, as programmable switches process packets at terabits per second rates [3, 5, 7].

Several specific classes of distributed systems have been developed or improved using these capabilities. In the domain of distributed storage, systems like CONCORDIA implement rack-scale distributed shared memory with in-network cache coherence, while MBalancer offloads bottleneck Memcached servers by identifying and duplicating hot keys directly in the data plane [1, 5]. Data plane programmability has also revitalized traditional network management applications, enabling unprecedented scale and granularity in monitoring, telemetry, virtual switching, consensus, resiliency, and load balancing [1]. 

Beyond traditional networking, in-network computing is being applied to artificial intelligence and scientific workloads. Integrating AI and machine learning workloads requires addressing hardware constraints through efficient algorithm design and model compression, with frameworks like Planter and Quark simplifying the development of intelligent applications [2, 4]. Additionally, in-network computing is being explored to improve performance and lower operational costs for scientific workloads executing on high-performance computing (HPC) platforms, such as simulation tools [6]. To support these diverse applications, specific in-network primitives have been developed; for instance, implementing custom floating-point arithmetic on programmable switches, such as NetFC, allows for accurate calculations using minimal memory and can be integrated with systems like Sonata to improve attack detection [3]. Specific systems demonstrate these gains clearly: NetCache processes over 2 billion queries per second, and ATP improves the training throughput of distributed deep learning systems by up to 66% through in-network gradient aggregation [3].

## Limitations and Open Problems
Despite these benefits, a major limitation of in-network computation on programmable switches is the severe scarcity of resources. Current hardware offers limited state storage, a restricted set of supported operations, and restricted computational capacity, such as supporting only simple integer arithmetic like addition and subtraction on Barefoot Tofino switches [1, 2, 3]. These hardware constraints make it infeasible to fully support certain applications on existing switch ASICs. For example, maintaining network sketches for multiple sub-populations or performing multi-dimensional sketch-based monitoring exceeds current on-chip compute and memory resources, necessitating efficient algorithm design and data reduction techniques to fit within the hardware limits [1, 2, 4].

The realization of a future-proof in-network computing ecosystem requires overcoming several open problems driven by current hardware constraints. Key challenges include developing programming language support for general applications, implementing runtime resource and state management, and ensuring fault tolerance across the data plane [2, 8]. Additionally, researchers must determine which control plane tasks can be optimally deployed on the data plane to maximize performance while navigating the strict limitations of programmable switching ASICs [2, 8]. Solving these ecosystem-level disconnects is essential to support the evolving demands of next-generation distributed applications.
